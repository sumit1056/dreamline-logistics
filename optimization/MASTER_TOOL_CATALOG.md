## 🛡️ 2. AI Collaboration & Traceability Field Guide (15 Habits)

**Source**: [AI-Collaboration-Field-Guide.pdf](file:///S:/optimization/AI-Collaboration-Field-Guide.pdf)  
**Philosophy**: *"Don't Just Trust the AI. Trace It."* — Turn AI-assisted coding from a gamble into a deterministic system you actually control.

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Handover Files  : Living record of status (done, in-progress, avoid)│
│ 2. Decisions.md    : Log WHY decisions and tradeoffs were made         │
│ 3. Flow.md         : Document how execution travels between modules    │
│ 4. Architecture.md : High-level system map & module dependencies       │
│ 5. Constraints.md  : Explicit list of what the AI must NEVER do        │
└────────────────────────────────────────────────────────────────────────┘
```

### 1️⃣ Handover Files (`Handover.md`)
- **Purpose**: A living record of project state read at the start of every session.
- **Contents**: What's done, what's in progress, what's broken, what to avoid.
- **Why It Matters**: Prevents session amnesia and eliminates re-explaining the project.

### 2️⃣ Decision Log (`KNOWLEDGE/DECISIONS.md` or `DECISIONS.md`)
- **Purpose**: Log every meaningful architectural decision and tradeoff made by the AI.
- **Contents**: Why library X over Y, why pattern Z was chosen, accepted tradeoffs.
- **Why It Matters**: Code shows *what* changed; `DECISIONS.md` shows *why*. Saves you from re-litigating settled arguments 6 months later.

### 3️⃣ Explicit Inline Comments
- **Purpose**: Require the AI to comment non-obvious logic as it writes code.
- **Contents**: Explain flow, caller expectations, and implicit assumptions (never restate obvious code).
- **Why It Matters**: Cheap insurance that lets future sessions understand intent without reverse-engineering from scratch.

### 4️⃣ Execution Flow Mapping (`FLOW.md`)
- **Purpose**: Document how execution travels between files, functions, and services.
- **Contents**: Order of calls, data transformations, and active modification paths.
- **Why It Matters**: Bugs live in the gaps between files. If you can't see the flow, you can't see where it breaks.

### 5️⃣ Feature & Bug Tracing (`BUG.md` / `FEATURE.md`)
- **Purpose**: Single file tracing a feature or bug from scope to verification.
- **Contents**: Discovery, attempts made, what worked, what failed, and verification proof.
- **Why It Matters**: Anyone (human or AI) can read cold and pick up exactly where work left off.

### 6️⃣ System Architecture (`ARCHITECTURE.md`)
- **Purpose**: High-level map of modules, services, and data pathways.
- **Why It Matters**: Enables the AI to reason about system impact before writing a single line.

### 7️⃣ Boundary Constraints (`CONSTRAINTS.md`)
- **Purpose**: Explicit list of off-limit files, patterns, and strict boundaries (e.g. *don't touch payment module*, *no new dependencies without asking*).
- **Why It Matters**: Turns blind "Allow" permissions into strictly scoped execution permissions.

### 8️⃣ Test & Verification Checklist (`TEST_CHECKLIST.md`)
- **Purpose**: Concrete commands and expected outputs before marking work as "done".
- **Why It Matters**: AI claiming success and code actually working are two different facts.

### 9️⃣ Rollback Plan (`ROLLBACK.md`)
- **Purpose**: Clear safety net for reversing large or risky edits.
- **Why It Matters**: Confidence to make big changes comes from knowing exactly how to undo them.

### Review Discipline & Meta Habits
- **10. Read Every Diff**: Never accept a change based on the AI's summary. Inspect line-by-line every time.
- **11. Ask "Why" Before "What"**: Require the AI to explain its plan and reasoning before generating code.
- **12. Small Requests Only**: One logical change per request for traceable diffs.
- **13. Session Handoff Summary**: End every session with a 5-line note (what we did, what's left, what to watch out for).
- **14. Version-Pin Context**: Note which AI model or version made which decision for future debugging.
- **15. Own the Mental Model**: Never accept code you cannot explain in your own words. Docs support understanding; they don't replace it.

## 🌐 3. Web Production Pre-Flight Checklist (20-Point Quality Audit)

A 20-point quality audit for web applications to ensure production readiness, fast load speeds, perfect SEO, and zero AI vibecoding giveaways.

### 🏷️ 1. SEO & Metadata Standards
- [ ] **Unique Page Titles**: Every page has a distinct, descriptive `<title>`.
- [ ] **Meta Description**: Proper `<meta name="description" content="...">` on all routes.
- [ ] **Open Graph (`og:image`)**: Valid Open Graph tags (`og:title`, `og:description`, `og:image`) for social preview cards.
- [ ] **Canonical URL**: Include `<link rel="canonical" href="...">` to prevent duplicate indexing issues.
- [ ] **Sitemap**: Generate valid `sitemap.xml` at site root.
- [ ] **Favicon**: Branded `favicon.ico` / icon SVG in site header (no default framework icons).

### ♿ 2. Semantic HTML & Accessibility
- [ ] **Strict `<h1>` Rule**: Exactly ONE `<h1>` tag per page (never 0, never multiple).
- [ ] **Language Attribution**: Document tag initialized with `<html lang="en">` (or appropriate language code).
- [ ] **Image Alt Text**: All `<img>` elements contain descriptive `alt="..."` attributes.
- [ ] **Structured Data**: Schema.org JSON-LD structured data included where relevant.

### ⚡ 3. Performance & Build Optimization
- [ ] **Bundle Optimization**: Code splitting and tree-shaking enforced (no monolithic 3.5MB+ single JS bundles).
- [ ] **Console Cleanliness**: Zero uncaught console errors or missing key warnings during user flows.
- [ ] **Custom 404 Page**: Branded 404 error page fallback instead of default framework screens.
- [ ] **Source Maps Scoped**: Hide or strip `.map` source maps from public production builds.

### 🤖 4. AI & Crawler Infrastructure
- [ ] **`llms.txt` Support**: Include `llms.txt` file at site root to guide AI scrapers/agents.
- [ ] **Robots Policy**: Properly configured `robots.txt` that allows indexing while protecting private routes.
- [ ] **Custom Domain**: Configured custom domain for production launch (migrated off default `*.vercel.app` preview domains).
- [ ] **Browser Boilerplate Cleaned**: All default framework titles (e.g. "Vite + React") stripped.
- [ ] **View Source Hydration**: Ensure SSR/SSG pre-renders initial markup (view-source is not empty `<div id="root"></div>`).

## 🔒 4. Backend Security Hardening Guide (6 Pre-Ship Prompts)

A 6-pillar security audit to run on all backend services and API routes before publishing or deploying to production.

### 🔒 1. Rate Limiting & Auth Protection
Add rate limiting appropriate to each endpoint type:
- **Auth Routes** (login, signup, password reset): Stricter limits using a combination of per-IP and per-account limits with exponential backoff (not hard lockout).
- **Public Endpoints**: Moderate rate limits to prevent scraper abuse.
- **Authenticated Actions**: Looser, configurable thresholds.
- **Rule**: All rate limit thresholds must be configurable via environment variables, not hardcoded.

### 🧪 2. Strict Input Validation (Schema Enforcement)
- Validate every incoming payload/query parameter against a strict schema (e.g. Zod, Joi, Yup, Pydantic).
- **Reject Invalid Input**: Immediately reject mismatched inputs with standard validation errors (don't just sanitize/escape).
- Verify type, maximum length, regex formats, and explicit allowed keys.

### 🔑 3. Secrets & Hardcoded Key Audit
- Scan the complete codebase for hardcoded API keys, JWT secrets, passwords, or tokens.
- Verify all credentials load strictly from environment variables (`.env`).
- Check that sensitive keys are never exposed in frontend bundles (e.g. `NEXT_PUBLIC_` or Vite env prefix leakages) or committed to Git (`.gitignore` audit).

### 📦 4. Dependency Vulnerability Audit
- Run package dependency vulnerability scans across the codebase (e.g., `npm audit`, `pip audit`, `cargo audit`).
- Identify packages with known vulnerabilities (CVEs), list severity levels, and patch/update/replace unsafe packages.

### 🚫 5. Error Masking & Information Leakage Guard
- Review all error handling logic across API endpoints.
- **Client Error Masking**: Ensure users never see raw database errors, stack traces, SQL syntax, or internal file paths. Return clean, generic messages.
- **Server Logging**: Log full diagnostic details and stack traces server-side for internal debugging.

### 📁 6. File Upload Safety & Execution Isolation
- **Content Inspection**: Validate actual file content (magic bytes / mime-type), size limits, and extensions.
- **Storage Isolation**: Store uploads outside the web root or in dedicated isolated object storage (e.g., AWS S3, Cloudflare R2).
- **Execution Prevention**: Ensure uploaded files can never be executed as server-side code (`.php`, `.exe`, `.sh`, `.js`).

## 📑 5. Component States & UX Flow Checklist (Checklist.design)

### Component State Completeness
When building any interactive UI component (button, input, modal, dropdown, select, table):
- [ ] **Default State**: Initial clean visual representation.
- [ ] **Hover State**: Subtle visual feedback on mouseover (`:hover`).
- [ ] **Active / Pressed State**: Visual click response (`:active`).
- [ ] **Focus State**: Visible keyboard focus ring for accessibility (`:focus-visible`).
- [ ] **Disabled State**: Muted colors, `aria-disabled="true"`, and pointer-events disabled.
- [ ] **Loading State**: Embedded spinner/skeleton state while async action completes.
- [ ] **Error State**: Red outline/message text for invalid form inputs.

### UX Flow Completeness
For every user journey (Auth, Payment, Upload, Filter, Onboarding):
- [ ] **Empty State**: Friendly zero-data visual card when lists/tables have no items.
- [ ] **Skeleton Loaders**: Smooth placeholder layout skeletons during initial data fetch.
- [ ] **Error Fallback Card**: Retry button and user-friendly error message if API fails.
- [ ] **Success Confirmation**: Toast or inline banner confirming action completion.

## ⚡ 17. App Performance Optimization Pack (5 Speed Prompts)

Fix the 5 most common performance gaps left behind by AI coding agents. Run one prompt at a time and verify performance after each run before proceeding to the next.

### 1️⃣ Compress API Responses in Transit
> *"Check whether my API responses are compressed in transit. Enable gzip or brotli compression on the server or edge for JSON and text responses above a small size threshold, and confirm the client negotiates it via Accept-Encoding. Avoid double-compressing already-compressed payloads. Verify response transfer sizes drop significantly and responses still parse correctly on the client."*

### 2️⃣ Batch Inserts and Updates
> *"Find code that performs many individual INSERT or UPDATE statements in a loop where a single batched operation would work. Replace them with bulk/batched writes (multi-row inserts, batch updates, or a single statement) inside an appropriate transaction. Chunk very large batches to avoid oversized statements or long locks. Verify write-heavy operations complete far faster with fewer round trips."*

### 3️⃣ Add Circuit Breaker for Slow Dependencies
> *"Identify external dependencies whose slowness or failures could cascade into my app, exhausting threads or connections while everyone waits. Add a circuit breaker that trips when a dependency is failing or too slow, fast-failing or serving a fallback until it recovers, with timeouts and limited concurrency to that dependency. Verify that a degraded dependency no longer drags down unrelated parts of the app and recovers cleanly."*

### 4️⃣ Apply Optimistic UI Updates
> *"Identify user actions (likes, toggles, adds, edits, deletes) that currently wait for the server response before updating the screen. Make them optimistic: update the UI immediately as if the action succeeded, then reconcile with the server result and roll back gracefully if it fails. Include clear error handling and a visible rollback so users aren't misled. Verify the happy path feels instant and failures restore the correct state."*

### 5️⃣ Cache Rendered Pages or Fragments
> *"Find server-rendered pages or fragments whose output is identical (or nearly so) across many users and changes infrequently. Cache the rendered output and serve it directly, regenerating on a schedule or on content change, while keeping personalized regions dynamic via holes or client-side hydration. Ensure cache keys account for meaningful variations like locale. Verify these pages serve much faster and rendering load decreases."*

> ⚠️ **Execution Discipline**: Test after running every single prompt! Touch caching, database writes, and network behavior one by one so you can pinpoint exact changes.
